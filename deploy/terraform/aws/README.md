# valkv-apg on AWS

A reference deployment. It is meant to be read, copied and changed, not used as a black box.

```
internet ─▶ network load balancer ─▶ nodes (auto-scaling group, private subnets)
                                        │ poll for configuration
                                        ▼
            internal load balancer ─▶ admin (auto-scaling group) ─▶ Postgres (RDS)
```

| Directory | What it holds |
|---|---|
| `modules/gateway` | Everything above: load balancers, both groups, the database, security groups, one secret, one log group |
| `environments/dev` | A small, cheap instance of the module. Copy it for staging and production |

The module creates no network. You give it a VPC, public subnets for the load balancer and private subnets for everything else. The private subnets need a route to the internet (a NAT gateway) so instances can pull images and reach an ACME authority.

## Apply

```sh
cd environments/dev
terraform init
terraform apply \
  -var vpc_id=vpc-0123456789abcdef0 \
  -var 'public_subnet_ids=["subnet-aaa","subnet-bbb"]' \
  -var 'private_subnet_ids=["subnet-ccc","subnet-ddd"]'
```

The outputs are:

- `traffic_dns_name`: point your domains at it.
- `admin_url`: the Admin API. It is reachable only from inside the VPC and from `admin_allowed_cidrs`.
- `secret_arn`: the secret that holds the encryption key, the two bootstrap tokens and the database URL.

Read the admin token and make a first call from a host inside the VPC:

```sh
token=$(aws secretsmanager get-secret-value --secret-id "$(terraform output -raw secret_arn)" \
  --query SecretString --output text | jq -r .admin_token)
curl -H "Authorization: Bearer $token" "$(terraform output -raw admin_url)/v1/services"
```

## What is protected, and how

- **The database** accepts connections from the admin's security group only. Nodes never talk to it.
- **The Admin API** sits behind an internal load balancer. Nodes and the networks you list may reach it; nothing else can.
- **The management port** of the nodes (health and metrics, 9100) is open to the VPC only.
- **Secrets** are generated by Terraform, kept in Secrets Manager, and read by instances at boot through their instance role. They are written to a root-only file on the instance and never appear on a command line. They are also in the Terraform state: keep the state in an encrypted bucket with restricted access.
- **Shell access** is through Session Manager. No SSH port is open.
- **Instance metadata** requires session tokens (IMDSv2) with a hop limit of 1, so containers cannot read the instance role's credentials.

## Things you will want to change

- **TLS for the Admin API.** The internal listener is plain HTTP. For anything beyond a private VPC, add a certificate and an HTTPS listener in `modules/gateway/main.tf` and change `admin_url` to match.
- **Remote state.** `environments/dev/main.tf` has a commented `backend "s3"` block.
- **Trusted proxies.** The network load balancer preserves the client address, so nodes need no `APG_TRUSTED_PROXIES`. If you put a CDN in front, pass its ranges through `node_env`.
- **Upstreams in the same VPC.** Allow the `node_security_group_id` output on their security groups. Nodes refuse private upstream addresses unless told otherwise; pass `APG_BACKEND_ALLOW_CIDRS` through `node_env`, and the same value to the admin.

## Upgrades

Change `version_tag` and apply. Both launch templates change, and each group replaces its instances in a rolling refresh: the admin first (at least half stay in service), then the nodes (at least 90 % stay in service). A node that is being replaced is taken out of the load balancer, given 30 seconds to finish its requests, and then stopped.

To go back, set `version_tag` to the previous release and apply again.

## Removing it

`terraform destroy`. In `dev` the database has no deletion protection and takes no final snapshot. Elsewhere the module's defaults keep both, and you must turn deletion protection off first.
